① Połączenie WebSocket + rola

→UI otwiera ws://host/ws
←serwer wysyła status (connected, firmware, session_id, role)
←sessions broadcast do wszystkich klientów
Role (jeden kontroler):
controller — wysyła akcje observer — tylko eventy pending — czeka na takeover
✕disconnect kontrolera → robot.stop() + TrainingRunner.stop() — auto
pierwszy observer → awansuje na controller

② Połączenie z robotem (BLE / USB)

→scan — BLE scan (timeout 8s)
←scan_result [{address, name, rssi}]
→connect {address}
BLE MLDP connect → firmware query
←status {connected: true, firmware, device}
←calibration_loaded {cal} z .calibration.json
→usb_scan → usb_ports
→usb_connect {port} → FTDI init (0x5A×2 @ 9600)
Auto-mechanizmy (background tasks):
⟳reconnect_loop co 15s jeśli !connected + znany adres
⏱standby_loop co 30s — robot.stop() po 5 min bezczynności

③ Kalibracja

→begin_calibration {cal}
cmd B/A: top_speed, bot_speed, osc, height, rot
silniki kręcą się (tryb "trzymaj")
→throw → set_ball + 300ms → T + 1500ms → H (stop)
←status po throw (motors off)
⬆REST PUT /api/calibration → zapis .calibration.json (per device addr)

④ Uruchomienie drilla (bez gracza)

→set_ball {top, bot, osc, h, rot, wait_ms}
cmd B/A do robota — silniki na żądany poziom
→run_drill {id, count, percent}
cmd T×count w pętli (percent skaluje wait_ms)
←drill_progress {ball, total, run} na każdą piłkę
←drill_ended po ostatniej piłce
→stop_drill → robot.stop() → cmd H
⚠ Nie zapisuje historii — brak gracza

⑤ Solo drill / exercise (z graczem)

→run_drill_solo {drill_id, player_id, record, count}
tworzy mini-trening: 3s countdown, 1 krok, pause=0
TrainingRunner.start(solo_drill_id=…)
←training_countdown / training_step / training_drill_progress
←training_ended → zapis do training_history (solo_drill_id)
→run_exercise_solo {exercise_id, player_id, record, duration_sec}
←training_exercise_progress {sec, total_sec}
←training_ended → zapis (solo_exercise_id)

⑥ Pełny trening (TrainingRunner)

Start:
→run_training {id, player_id, record, record_type, start_from_step}
←training_info {name, total_steps, phase: "countdown"}
←training_countdown {sec} × countdown_sec
Na każdy krok (drill):
←training_step {step, total, drill_name, count, percent, balls, est_remaining_sec}
robot.run_drill(balls, count, percent)
←training_drill_progress {ball, total_steps, est_remaining_sec}
←training_step_done
←training_pause {sec, next_drill} — odliczanie przerwy
Na każdy krok (exercise):
←training_step {phase: "exercise", exercise, duration_sec}
←training_exercise_progress {sec, total_sec, description}
←training_step_done
Kontrola w trakcie:
→pause_training → training_paused
→resume_training → training_resumed
→skip_training → pomija krok / przerwę
→training_note {step, note} — notatka do kroku
→set_next_percent {percent} → training_percent_changed
→stop_training → status "stopped"
←training_ended {elapsed_sec} → zapis training_history

⑦ Protokół robota (BLE / USB)

Komendy wysyłane przez transport:
B/Aset_ball — prędkości + osc + height + rot Tthrow — rzut jednej piłki (trigger) Hstop — wyłącz silniki wTAfirmware ≥ 701: konfiguracja silników górnych ?Vzapytanie o wersję firmware
Kluczowe wartości:
centrum = 150 (nie 128!) osc 127–173 height 75–210 rot 90–210
speed_raw × 4.016 = PWM BLE: \r · USB: \r\n USB init: 0x5A × 2 @ 9600

Gracze:

⑨ Przejęcie kontroli (multi-klient)

Klient B chce przejąć:
→request_takeover
B → role: pending
←takeover_request → do kontrolera A
Kontroler A odpowiada:
→respond_takeover {accepted: true/false}
accepted: A→observer, B→controller
rejected: B→observer
Timeout / rezygnacja:
→cancel_takeover → B→observer
→release_control → A→observer, pierwszy pending→controller
←sessions broadcast po każdej zmianie ról
